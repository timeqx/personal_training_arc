# Practice Routine

The goal is deliberate practice, not maximum hours.

## Default weekly structure

### Monday — Learn + recall
- 45 min primary reading.
- 45 min handwritten/typed explanation from memory.
- 60 min coding drills.
- 15 min error journal.

### Tuesday — Implementation
- 90 min build from memory.
- 45 min tests.
- 30 min code review of your own work.
- 15 min flash review.

### Wednesday — Debugging day
Take broken code or deliberately break your project:
- compiler errors,
- race/deadlock,
- failed tests,
- retrieval regression,
- malformed tool calls,
- deployment failure.

Spend at least half the session diagnosing before asking an AI agent for the answer.

### Thursday — Theory + interview
- 45 min math/systems/AI theory.
- 45 min explain one concept aloud.
- 45 min interview coding.
- 30 min design question.

### Friday — Integration
Combine topics:
- Rust + PostgreSQL,
- Rust + async API,
- AI + evaluation,
- MCP + permissions,
- RAG + observability.

### Weekend — Project + exam
- 2–4 hour capstone/project block.
- 30–60 minute exam.
- weekly retrospective.
- update scorecard.

# Daily micro-drills

Choose 3–5.

## Rust
- predict whether code compiles,
- fix one borrow-checker problem without cloning first,
- implement one trait,
- refactor one match,
- write one iterator chain,
- write one test,
- interpret one compiler diagnostic.

## AI/ML
- derive/explain one metric,
- implement one small formula,
- inspect one model error,
- compare two retrieval results,
- label five eval examples,
- explain one transformer component.

## Systems
- inspect one Linux process,
- EXPLAIN one SQL query,
- read one network trace,
- draw one architecture,
- identify one failure mode.

## Interview
- one easy/medium data-structure problem,
- one behavioral answer,
- one system-design subproblem.

---

# No-AI practice blocks

At least **three sessions per week** should contain a 30–60 minute block where AI coding assistants are disabled.

Use them for:
- ownership drills,
- coding interview questions,
- ML derivations,
- debugging,
- architecture design.

After your attempt, use an AI reviewer to:
- find missed cases,
- challenge your explanation,
- propose alternative designs.

This builds ability rather than dependency.

# Weekly retrospective

Answer:
1. What can I now do without notes?
2. What did I only copy?
3. What bug taught me the most?
4. What concept still feels fuzzy?
5. Which benchmark/eval changed my belief?
6. What did I ship?
7. What should I stop spending time on?
8. What will I prove next week?

---

# Monthly checkpoint

Every four weeks:
- retake one old exam without reviewing the answers,
- implement one prior exercise from scratch,
- revisit a project and simplify it,
- publish one technical writeup or architecture note,
- update résumé only with newly evidenced skills.
